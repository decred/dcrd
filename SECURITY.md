# Security Policy

## Reporting a Vulnerability

Please do not disclose security vulnerabilities through public GitHub issues,
discussions, or pull requests.

Instead, report suspected security vulnerabilities privately through [GitHub's
private vulnerability reporting
feature](https://github.com/decred/dcrd/security/advisories/new).

Reports should include sufficient technical detail to allow the issue to be
independently evaluated and reproduced. In particular, please include:

- The affected repository, version, branch, or commit
- A description of the vulnerability and its potential security impact
- The conditions required to trigger or exploit the vulnerability
- Clear reproduction steps and, where practical, a proof of concept
- Any relevant configuration or environmental requirements

Reports should demonstrate a concrete security impact rather than rely solely on
theoretical concerns, automated analysis output, or speculative attack
scenarios.

The maintainers will review reports, assess their validity and severity, and
coordinate remediation and disclosure as appropriate. Reporters are encouraged
to coordinate disclosure with the maintainers and allow reasonable time for
affected users to receive a fix before publicly disclosing the vulnerability.

The Decred project does not operate a bug bounty program and does not offer
financial compensation for vulnerability reports.

## Supported Versions

Security vulnerabilities must be reproducible in the latest production release
or the master branch of the code.
